## Solution layout

This is an **ABP Framework v10.1.1** monolith on **.NET 10** with a Blazor Server UI and three in-repo ABP modules. The solution root is the parent of `src/` — do not treat `src/` as the repo root.

- `src/` — host application (`patisserie_shop.*` projects). Entry point: `patisserie_shop.Blazor` (Blazor Server). DB schema owner: `patisserie_shop.EntityFrameworkCore` + `patisserie_shop.DbMigrator`.
- `modules/{inventory,operations,intelligence}/src/` — independent ABP modules. Each repeats the full layered structure (`Domain.Shared`, `Domain`, `Application.Contracts`, `Application`, `EntityFrameworkCore`, `HttpApi`, `HttpApi.Client`, `Installer`).
- `test/` — xUnit test projects + `patisserie_shop.TestBase` shared fixtures.
- `etc/scripts/` — PowerShell scripts that wrap common dotnet/abp workflows.
- See [ABP_STRUCTURE.md](ABP_STRUCTURE.md) for a full architectural breakdown (layers, module integration via `[DependsOn]`, technology stack).

## Module integration model

Modules are wired into the host **per layer** via ABP's `[DependsOn]` attribute on each module class:
- `patisserie_shopDomainModule` depends on `{Inventory,Operations,Intelligence}DomainModule`
- `patisserie_shopApplicationModule` depends on each module's `ApplicationModule`
- `patisserie_shopEntityFrameworkCoreModule` depends on each module's `EntityFrameworkCoreModule`
- `patisserie_shopBlazorModule` depends on each module's `ApplicationContractsModule`

When adding cross-cutting wiring (a new module dependency, a new permission provider, an EF mapping), update the corresponding host module class **and** the matching `.csproj` `<ProjectReference>` — both are required.

## Common commands

All commands run from the **solution root** unless noted.

### First-time setup
```powershell
./etc/scripts/initialize-solution.ps1
```
Runs in parallel: `abp install-libs` (client-side packages), `dotnet run` twice in `src/patisserie_shop.DbMigrator` (creates DB + seeds), and generates `openiddict.pfx` dev cert in `src/patisserie_shop.Blazor`.

### Run the app
```powershell
dotnet run --project src/patisserie_shop.Blazor
```
Default URL: `https://localhost:44387` (matches `AuthServer:Authority` — changing the port requires updating `appsettings.json`).

### Database migrations
EF migrations live in `src/patisserie_shop.EntityFrameworkCore/Migrations`. The DbMigrator project is the **only** sanctioned way to apply migrations and seeders.
```powershell
# Add a migration (host schema)
dotnet ef migrations add <Name> -p src/patisserie_shop.EntityFrameworkCore

# Apply migrations + run seeders
./etc/scripts/migrate-database.ps1
# or directly:
dotnet run --project src/patisserie_shop.DbMigrator
```
Each module also owns its own EF migrations under `modules/<module>/src/<Module>.EntityFrameworkCore/Migrations`; the host DbMigrator applies all of them in one pass.

### Tests
```powershell
# All tests
dotnet test

# Single project
dotnet test test/patisserie_shop.Application.Tests

# Single test by fully-qualified name
dotnet test --filter "FullyQualifiedName~Namespace.ClassName.MethodName"
```

### Build
```powershell
dotnet build patisserie_shop.slnx     # new VS solution file
# or
dotnet build src/src.sln              # host-only solution
```

## Database & auth

- **Database**: PostgreSQL. Connection string in `src/patisserie_shop.Blazor/appsettings.json` and `src/patisserie_shop.DbMigrator/appsettings.json`. Default DB name is `patisserie`.
- **Auth**: OpenIddict (self-hosted). Requires `openiddict.pfx` in `src/patisserie_shop.Blazor` — generated by `initialize-solution.ps1` for dev. For production, generate a real cert (see [README.md](README.md)).

## Conventions

- **Auto API controllers**: REST endpoints are **not hand-written** — they are auto-generated from `IApplicationService` interfaces in each `*.Application.Contracts` project. To expose a new endpoint, add the method to the interface and implement it in the matching `*.Application` project.
- **DI container**: Autofac (configured via ABP).
- **Object mapping**: Mapperly (see `patisserie_shopBlazorMappers.cs` for the host pattern).
- **Theme**: LeptonX Lite v5.1.1 — client-side libs are managed via `abp install-libs` (re-run after pulling if you see missing CSS/JS).
- **Nullable reference types**: enabled solution-wide via `common.props`.
- `common.props` is imported by both host and module `.csproj` files — solution-wide MSBuild properties belong there, not in individual projects.
